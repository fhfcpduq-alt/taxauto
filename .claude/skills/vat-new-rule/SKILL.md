# vat-new-rule — 사람 결정을 규칙으로 올리기

엔진이 AI와 함께 발전하는 고리다. 사람이 한 번 내린 결정은 거래처 메모리(`clients/{id}/memory.yaml`)에 쌓인다.
같은 판단이 여러 거래처에서 반복되면 공용 룰(`config/rules/purchase.yaml`)로 올린다.
그러면 다음부터 AI 호출 없이 결정적으로 처리되고, 사람 확인도 줄어든다.

## 언제 쓰나

- 아침 검토에서 같은 가맹점·같은 판단을 세 번 이상 반복했다.
- 여러 거래처 메모리에 같은 성격의 결정이 있다. 예: 골프장은 모두 `불공제/사업과직접관련없는지출`.
- AI 판정(`decided_by=llm`)이 같은 패턴에서 계속 사람에게 뒤집힌다.

## 절차

1. **후보 수집** (읽기만)
   - `clients/*/memory.yaml` 의 `entries` 를 모은다. `classification` 과 `example.counterparty_name` 기준으로 묶는다.
   - `data/{period}/*/decisions.jsonl` 에서 `by` 가 사람인 재분류 기록을 모은다.
   - MCP `list_review_items(period, open_only=False)` 에서 `확인후유지`·`해결` 항목의 `resolution` 문장을 모은다.
2. **패턴 정리.** 후보마다 아래 표를 만든다.
   | 패턴(가맹점·업종·품목) | 결정(분류/사유) | 근거 건수 | 거래처 수 | 반례 |
   반례가 하나라도 있으면(같은 패턴인데 다르게 결정한 경우) 공용 룰로 올리지 않는다. 거래처 메모리에만 둔다.
3. **어디로 올릴지 정한다.**
   - 거래처 한 곳만의 사정(그 집 대표 차량, 그 거래처만의 복리후생 등) → 거래처 메모리. 이미 있으면 그대로 둔다.
   - 2곳 이상, 반례 없음, 세법상 일반적 → 공용 룰 초안.
   - 세법 판단이 애매하면 → 룰로 만들되 `needs_review: true`, `confidence` 0.6~0.8 로 둔다. 자동으로 확정하지 않는다.
4. **룰 초안 작성.** `config/rules/purchase.yaml` 맨 위 주석의 `when`/`then` 문법을 따른다.
   - `id` 는 영문 소문자_밑줄. 같은 id 가 없는지 확인한다.
   - 위치: 첫 번째로 맞는 룰 하나만 적용된다. 더 구체적인 룰을 더 일반적인 룰보다 위에 둔다.
   - 금액 기준은 숫자를 쓰지 말고 `policy:` 경로를 쓴다. 세법 숫자는 `config/law/` 키를 참조한다.
   - `note` 에 근거를 쓴다. 조문을 모르면 "사람 결정 n건 기반"이라고만 쓴다. 조문을 지어내지 않는다.
5. **검증.**
   - `python -m pytest -q` 전체 통과.
   - 지난 회차를 다시 돌려 차이를 본다: `taxauto run --period {지난회차} --from-stage classify`. 그다음 `_summary.json` 의 `final_tax` 가 바뀐 거래처를 확인한다. 바뀐 이유가 이 룰 때문인지 하나씩 설명할 수 있어야 한다.
6. **사람 승인.** 룰 diff, 근거 표, 영향받은 거래처·세액 변화를 세무사에게 보여주고 승인받는다.
   승인 전에는 커밋하지 않는다. 커밋 메시지에 승인자 이름을 적는다.
7. **정리.** 공용 룰로 덮이는 거래처 메모리 항목은 남겨 둬도 된다(메모리가 룰보다 먼저 적용되지만 결과가 같음).
   지우려면 사람 승인을 받는다.

## 하지 말 것

- 사람 승인 없이 `config/rules/` 나 `clients/*/memory.yaml` 을 바꾸지 않는다.
- `config/law/*.yaml`(세법 숫자)은 이 절차로 바꾸지 않는다. 세법검증 절차를 따른다.
- 거래처 실명·사업자번호를 룰 파일에 넣지 않는다. 공용 룰은 업종·가맹점 유형 기준으로 만든다. 특정 거래처는 메모리로 처리한다.
- 반례가 있는 패턴을 "대부분 그렇다"는 이유로 공용 룰에 넣지 않는다.
