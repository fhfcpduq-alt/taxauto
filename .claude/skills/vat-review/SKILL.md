# vat-review — 아침 검토 (사람과 함께)

## 전제

- 사람(세무사·직원)이 옆에 있다. **결정은 사람이 한다.** Claude는 근거를 정리하고 선택지를 내고, 사람이 고른 결정을 기록한다.
- 역할 분담:
  - **엔진**(MCP `taxauto`)은 판정·재계산·검증·작업지시서를 맡는다.
  - **위하고 화면 수정**은 `wehago-operator` 스킬이 한다. 사람이 직접 고쳐도 된다.
  - 이 대화에서는 "무엇을 고칠지"를 정하고 기록한다.
- 금액·세액·기한은 도구 결과만 인용한다. 직접 계산하지 않는다.

## 절차

1. **오늘 상황 (2~3줄)**
   - `list_filings()` → 기한·D-day, 신고 가능 n곳, 차단 있는 곳 n곳, 실패 n곳.
   - 어젯밤 `vat-night-run` 이 남긴 "에이전트 후처리" 절이 `_briefing.md` 에 있으면 함께 요약한다.
   - 처리 순서를 제안한다. **차단 많은 곳 → D-day 가까운 곳 → 경고만 남은 곳.**
2. **거래처 하나씩**
   - `get_filing(client_id, period)` 로 결론(납부/환급세액·기한), 미해결 항목, 위하고 대사 차이(`wehago_diff`)를 짧게 보여준다.
   - 항목마다:
     1. 무엇이 문제인지 한 줄, 세액 영향, 관련 거래(`get_transactions` 또는 항목의 `tx_ids`).
     2. 선택지 2~3개와 각각의 결과(어느 칸이 얼마 바뀌는지는 재실행 뒤 도구 결과로 확인).
     3. 사람이 고르면 기록한다.
        - 분류를 바꾼다: `reclassify_transaction(..., decided_by="<결정한 사람 이름>", reason=…)`.
          compute→validate→report 가 다시 돌고 새 세액이 나온다.
        - 그대로 둔다: `resolve_review_item(..., status="확인후유지", note="근거", resolved_by="<이름>")`.
        - 고쳤다(위하고 수정·자료 보완 완료): `status="해결"`.
     4. "다음부터 이 가맹점은 자동으로?" 라고 **물어본다.** 사람이 "예"라고 하면 `remember=True`.
   - AI가 밤에 1차 판정한 거래(`decided_by=llm`)는 사람이 확인하면 `decided_by=<이름>` 으로 다시 기록한다. 그래야 확정된다.
3. **위하고 반영**
   - 분류가 바뀌었거나 차단이 해결된 거래처는 `get_work_order` 로 지시서를 확인한다.
   - 사람이 원하면 `wehago-operator` 스킬로 넘긴다. 직접 고칠 때는 `report/review_items.xlsx` 의 "해당거래" 시트를 쓴다.
   - 위하고 신고서를 다시 내려받으면 `ingest_file` 로 넣는다. 그다음 `get_filing` 의 `wehago_diff` 가 비었는지 본다.
4. **마무리**
   - 차단 0, 대사 일치 → "신고 가능"으로 정리한다. **제출은 사람이 한다.**
   - `draft_client_message` 로 카톡 초안을 보여준다. `sendable=false` 면 이유를 말하고 보내지 말라고 한다.
     문장은 다듬어도 되지만 숫자·기한은 바꾸지 않는다. 과한 공손체·이모지는 쓰지 않는다.
   - 같은 결정을 오늘 세 번 이상 했다면 `vat-new-rule` 로 룰 승격을 제안한다.

## 말투

- 짧게. 결론 먼저, 근거는 한두 줄.
- 세법은 확실한 것만 말한다. 애매하면 "확인 필요"라고 하고, 무엇을 확인해야 하는지 말한다.

## 하지 말 것

- 사람 확인 없이 `resolve_review_item`, `remember=True`, `decided_by=<사람이름>` 쓰기.
- 전자신고 제출, 제출 화면 열기.
- 카톡 직접 발송(초안만 만든다).
- 주민등록번호·카드번호 전체를 대화·note 에 그대로 쓰기.
