# 아키텍처 — 어떤 에이전트 모델로 갈 것인가

## 결론

**"자체 엔진 + MCP 도구 + Claude 에이전트" 하이브리드**로 간다.

- 반복되고 정답이 있는 일(집계·대사·검증·가산세 추정)은 **자체 엔진(결정적 코드)** 이 맡는다.
- 판단이 필요한 일(애매한 매입 분류, 예외 원인 분석, 거래처 안내문, 화면 조작)은 **Claude** 가 맡는다.
- 둘 사이는 **MCP(표준 도구 인터페이스)** 로 연결해서, AI 모델이 바뀌어도 엔진은 그대로 쓴다.

| 방식 | 점수 | 판단 |
|---|---|---|
| A. 매번 Claude에 명령해서 처리 | 45 | 처음엔 빠르지만, 같은 자료를 넣어도 결과가 매번 조금씩 다르다. 누가 어떤 근거로 처리했는지 기록이 남지 않는다. 거래처 수만큼 토큰이 나가고, 밤새 혼자 돌리기엔 불안정하다. 세액 계산을 LLM이 하면 안 된다. |
| B. 자체 툴(RPA·스크립트)만 | 60 | 결과가 재현되고 비용이 싸다. 대신 위하고 화면이 바뀌면 깨지고, 예외 판단을 못 해서 결국 사람이 다 본다. AI가 좋아져도 그 이득을 못 가져온다. |
| **C. 엔진 + MCP + 에이전트 (채택)** | **88** | 계산은 코드가 하니 정확하고 감사 추적이 된다. 판단만 AI가 하고, 모델이 좋아질수록 자동 처리 범위가 넓어진다. |

## 3층 구조

```
┌───────────────────────────────────────────────────────────────┐
│ 3. 에이전트 층 (교체 가능: Claude Code / Agent SDK / 다음 세대 모델)  │
│    .claude/skills/  vat-night-run · vat-review · vat-new-rule       │
│    - 실패 원인 분석, 애매한 매입 1차 판정, 안내문, (향후) 화면 조작        │
└──────────────▲────────────────────────────────────────────────┘
               │ MCP (표준 도구 호출)  ← 여기가 '안 바뀌는 계약'
┌──────────────┴────────────────────────────────────────────────┐
│ 2. 도구 층  src/taxauto/agent/mcp_server.py                        │
│    list_filings · get_filing · list_review_items · resolve ·       │
│    reclassify_transaction · run_pipeline · draft_client_message    │
│    (제출·삭제 도구는 의도적으로 없음)                                  │
└──────────────▲────────────────────────────────────────────────┘
┌──────────────┴────────────────────────────────────────────────┐
│ 1. 엔진 층 (결정적, 테스트됨)  src/taxauto/                          │
│  collect → normalize → enrich → classify → compute → validate → report │
│  세법 숫자 = config/law/*.yaml (적용기간·근거·검증여부)               │
│  사무실 기준 = config/policy.yaml                                  │
│  거래처 학습 = clients/{id}/memory.yaml                            │
└───────────────────────────────────────────────────────────────┘
```

## 부가세 실무 흐름별 자동화 수준

| 단계 | 지금 사람이 하는 일 | 자동화 | 방법 |
|---|---|---|---|
| 1. 자료 수집 | 홈택스·위하고에서 거래처별 조회·다운로드 | **부분 구현** | L0: 내려받은 파일(수임처 일괄 파일 포함)을 `inbox/`에 넣으면 밤에 자동 분배·인식. L1: Playwright 레시피로 다운로드 자동화(실계정으로 녹화해야 함). 홈택스 직접 로그인 자동화는 공동인증서·보안모듈 때문에 **현실적으로 어려움, 비추천** |
| 2. 정규화·중복제거 | 엑셀 정리, 중복 확인 | **구현** | 헤더 별칭 기반 자동 인식, 승인번호 기준 중복 제거 |
| 3. 상대방 상태 확인 | 폐업자·간이과세자 일일이 조회 | **구현** | 국세청 사업자 상태조회 공공 API(무료, 키 발급 필요) |
| 4. 매입 공제 판정 | 카드매입 공제/불공제 체크 | **구현 + AI** | 규칙 → 거래처 메모리 → (선택) Claude. 사람 결정은 메모리로 학습 |
| 5. 신고서 작성 | 위하고 자동집계 확인 | **구현(독립 재계산)** | 위하고 집계를 대신하는 게 아니라 **별도로 다시 계산해서 위하고 결과와 대사**한다. 두 번째 검토자 역할 |
| 6. 검증 | 세무사·직원 눈 검토 | **구현** | V001~V020 검증룰. 예외만 검토 큐로 |
| 7. 위하고 반영 | 전표 수정·불공제 전환 | **부분 구현** | 수정할 목록(엑셀)까지 자동. 위하고에 입력하는 건 사람(또는 향후 L2 에이전트) |
| 8. 전자신고 제출 | 홈택스 제출 | **자동화 안 함(의도)** | 세무대리인 책임 영역. 사람이 승인하고 제출 |
| 9. 거래처 안내 | 카톡으로 납부세액 안내 | **구현(초안)** | 차단 항목 남아 있으면 '발송 금지' 표시 |

## 밤에 돌아가는 방식

**실행 위치: 사무실 상시가동 PC(Windows) + 작업 스케줄러.**
클라우드는 공동인증서와 위하고 세션을 둘 수 없어서 맞지 않는다.

```
[낮] 직원/레시피가 inbox/{회차}/ 에 자료 투입  (수임처 일괄 파일이면 _bulk/ 에 그대로)
[02:00] scripts/night_run.ps1
        ├─ taxauto night       : 전 거래처 파이프라인 (거래처 하나가 실패해도 나머지는 계속)
        ├─ (선택) claude -p    : vat-night-run 스킬. 실패 원인 분석·애매한 매입 1차 판정
        └─ data/{회차}/_briefing.md, _dashboard.html, _summary.json
[아침] 세무사: 브리핑 → 차단 항목부터 처리 → (필요시 Claude와 vat-review) → 위하고 반영 → 제출
```

`_summary.json` 은 스키마가 고정돼 있다. 사무실 업무비서(M) 같은 다른 시스템이 아침 브리핑에 그대로 가져다 쓸 수 있다.

## AI가 발전해도 버리지 않는 장치

1. **세법은 데이터로 둔다.** 세율·한도·기한은 YAML에 적용기간을 붙여서 관리한다. 개정되면 한 줄만 추가하면 되고, 코드는 고치지 않는다.
2. **모델명은 설정 한 줄이다.** `policy.yaml`의 `llm.model`만 바꾸면 새 모델로 넘어간다.
3. **도구는 MCP 표준이다.** Claude 다음 버전이든 다른 에이전트든 같은 도구를 그대로 호출한다.
4. **절차는 Skill 문서로 둔다.** 업무 절차가 프롬프트가 아니라 저장소 파일로 남는다. 모델이 바뀌어도 그대로 읽힌다.
5. **신뢰도 임계값으로 자동화 범위를 정한다.** `llm_auto_accept_confidence` 하나로 조절한다. 모델이 좋아지면 이 값만 낮춰서 자동 처리 범위를 넓힌다.
6. **사람 결정을 규칙으로 올린다.** 사람이 한 번 내린 판정은 거래처 메모리에 저장된다. 다음부터는 AI 호출 없이 결정적으로 처리된다. 같은 결정이 반복되면 `vat-new-rule` 스킬로 공용 규칙으로 승격한다. 시간이 지날수록 AI 비용은 줄고 자동 처리율은 오른다.
7. **커넥터는 단계적으로 올린다.** L0 폴더 → L1 녹화 레시피 → L2 브라우저 에이전트(AI 화면조작) 순서다. 수집 방식이 바뀌어도 엔진은 그대로다.
8. **(로드맵) 평가셋을 만든다.** 이미 신고한 회차의 실제 신고서를 정답으로 쌓아 둔다. 새 모델·새 규칙을 넣을 때마다 "정말 나아졌는지" 숫자로 확인한다.

## 범위 밖(v1)

- 간이과세자 신고서: 차단 항목으로만 표시한다.
- 의제매입세액 한도 정산, 공통매입세액 안분·정산, 대손세액: 후보 집계와 경고까지만 한다. 최종 판단은 사람이 한다.
- 홈택스 전자신고 파일 생성·제출: 위하고 기능을 쓴다.
